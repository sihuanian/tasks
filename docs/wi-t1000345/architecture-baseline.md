## 交付形态与技术承载

交付物为**单个静态 SVG 文件**，路径约定为 `docs/wi-t1000345/sunflower.svg`。选择 SVG 的理由：

1. 单文件、自包含，全部图元内联于文件内，满足"不依赖外部资源或服务"的 AC-01 硬约束；
2. 浏览器可直接打开渲染（file:// 或任意静态托管），矢量缩放不失真；
3. 与需求推荐基线（SVG/PNG 静态图形）一致，且文本化格式便于实现阶段自检与验收阶段肉眼核对。

需求允许的 PNG 派生输出**不在本设计范围内**：若后续用户明确提出图片查看器兼容性需求，可由实现阶段从同一 SVG 补充导出，不影响当前架构结论（保守、可逆）。

## 画面内容与实现要素

SVG 内部按"一朵完整向日葵"组织四个可辨识图层（自下而上渲染）：

| 要素 | 技术承载 | 可辨识性要求 |
| --- | --- | --- |
| 茎 | 单条绿色 `path`（略带弧度的垂直线段，圆头描边） | 从花盘下方延伸至画面底部 |
| 叶片 | 2 片绿色椭圆/心形 `path`，分列茎的两侧，含浅色叶脉描边 | 与茎自然连接，绿色与茎区分可选 |
| 花盘（管状花） | 棕色 `circle` 底色 + 内部螺旋点阵（`g` 分组、按黄金角 ~137.5° 极坐标排布的小圆点），外圈可加一圈深棕环 | 位于花瓣中央，明显区别于花瓣区 |
| 花瓣（舌状花） | 一圈金黄色水滴形/披针形 `path`，用同一花瓣图元 + `transform: rotate` 环心阵列排布（建议 16–24 片） | 自花盘外缘放射，黄色与棕色花盘形成强对比 |

颜色、花瓣/叶片数量、构图角度均为需求"未规定事项"，以上取值为实现基线建议而非验收约束；唯一约束是**四类要素在渲染后肉眼可分别辨认**（AC-01）。

## 页面与交互范围

- 无应用页面、无路由、无组件树、无交互逻辑、无动画；不引入 React/Vite SPA 脚手架（交付物是文件本身，不是可操作应用）。
- 无浏览器持久化状态：不使用 localStorage/IndexedDB，无数据归属问题；唯一的"状态"即 SVG 文件内容本身。
- 无服务/API、无数据库、无认证、无后台任务、无外部集成、无跨设备/跨用户同步（与 classify 证据一致，需求第 5 行明确排除业务系统集成）。

- 查看入口：在操作系统中双击 `sunflower.svg`（浏览器或支持 SVG 的图片查看器/Quick Look 渲染），或在浏览器中通过“打开文件”加载；均直接渲染，无启动命令、无本地服务器依赖。
